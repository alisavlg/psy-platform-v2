Привет. Я делаю Eupsy — платформу для психологов.

Философия: Eupsy — от греческого εὐψυχία («благая душа»). 
Общество не может быть здоровым, если его души больны. 
Благое общество состоит из благих душ. Eupsy — среда, где 
психолог и клиент встречаются без лишних контактов.

Стек v2:
- **Фронтенд:** HTML + CSS + JS (модули) + Vite.
- **Бэкенд:** Supabase (Auth, PostgreSQL, RLS, Storage).
- **Хостинг:** VPS в Serv-Tech (IP `185.170.10.206`).
- **Видеосвязь:** WebRTC + собственный TURN-сервер (Coturn) на VPS.
- **Почта:** Postfix + OpenDKIM (собственный SMTP на VPS).
- **Репозиторий:** github.com/alisavlg/psy-platform-v2

Что происходит: переписываю проект в v2.
v2: public/ для HTML, src/ для JS/CSS. Модули. Стили через import в JS.

Что переведено: login.html, client.html, dashboard.html, admin.html.
Что осталось: Единый профиль для всех ролей, починка мессенджера, настройка RLS, единый календарь.

**Главные принципы архитектуры (ЗАФИКСИРОВАНО):**
1.  **Код пишется один раз.** Не дублируется. Компоненты (Профиль, Календарь, Мессенджер) используются во всех кабинетах, но меняют вид и функционал в зависимости от роли (`window.CURRENT_USER`).
2.  **Один аккаунт — много ролей.** Абонент может быть и клиентом, и психологом, и поддержкой. Кабинеты переключаются через меню аватара.
3.  **Единый календарь.** У всех пользователей один календарь, где видны все события (сессии, слоты, смены, личные дела). Редактировать можно только в соответствующем кабинете.
4.  **Конфиденциальность.** Клиент всегда анонимен для психолога (псевдоним и аватар). Психолог не видит реальных ФИО и контактов клиента.
5.  **RLS (Row Level Security).** Включен на всех таблицах. Пользователь видит только свои данные. Админ — всё.
6.  **Видеосвязь (WebRTC) — НЕ ТРОГАТЬ.** Работает. Любые изменения в `room.js` или TURN-сервере только после согласования.

**Правила работы:**
1.  **Сначала логика — потом код.** Не писать код, пока не согласована архитектура и план.
2.  **Запрашивай файлы перед правками.** Не гадать, а смотреть, как устроен текущий код.
3.  **Точечные правки — экономия чата.** Не переписывать файлы целиком без запроса.
4.  **Если файл уже ломался — предложи замену целиком.**
5.  **После каждой закрытой задачи — обновляй `state.md` и `architecture.md`.**
6.  **Один шаг — одна проверка.** Не делать 10 изменений сразу.
