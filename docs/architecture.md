## 2. Технологический стек
- **Фронтенд:** HTML, Vanilla JS (ES Modules), CSS. Сборщик — Vite.
- **Бэкенд:** Supabase (Auth, PostgreSQL, RLS, Storage).
- **Хостинг:** VPS в Serv-Tech (IP `185.170.10.206`).
- **Веб-сервер:** Nginx (раздача статики из `/var/www/eupsy/dist/`).
- **Видеосвязь:** WebRTC + собственный TURN-сервер (Coturn) на VPS.
- **SSL:** Let's Encrypt (Certbot).
- **Почта:** Postfix + OpenDKIM (собственный SMTP на VPS).

## 3. Ключевые принципы архитектуры (Единый код)

**Главный принцип:** Код пишется один раз. Компоненты (Профиль, Календарь, Мессенджер) используются во всех кабинетах, но меняют вид и функционал в зависимости от роли (`window.CURRENT_USER`).

**Аккаунт и Роли:**
- **Аккаунт:** Один email, один пароль. Это физический человек (например, Алиса).
- **Роли:** У аккаунта может быть несколько ролей: Клиент, Психолог, Сотрудник Поддержки, Администратор.
- **Личные кабинеты:** Каждая роль имеет свой кабинет (интерфейс, меню). При переключении роли меняется кабинет, но данные (профиль, календарь) остаются связанными с аккаунтом.

**Службы (для чатов и доступа):**
- **Служба Клиентов:** Все, у кого есть роль `client`. Абонент в этой службе — Клиент.
- **Служба Психологов:** Все, у кого есть роль `psychologist`. Абонент в этой службе — Психолог.
- **Служба Поддержки Клиентов:** Сотрудники с ролью `support`, которые отвечают клиентам.
- **Служба Поддержки Психологов:** Сотрудники с ролью `support-psy`, которые отвечают психологам.

**Чаты (через Партнера):**
- Партнер — это «переключатель», который указывает, к какой службе относится чат.
- Клиент пишет в Службу Поддержки Клиентов. Партнер = ID Службы Поддержки Клиентов.
- Психолог пишет в Службу Поддержки Психологов. Партнер = ID Службы Поддержки Психологов.
- Клиент пишет Психологу (Ивану). Партнер = ID Ивана (как психолога).

**Календарь (Единый):**
- У аккаунта **один** календарь. В нём видны все события (личные дела, сессии, слоты, смены), независимо от роли.
- **Редактирование:** В кабинете Клиента можно добавить только «Личное». В кабинете Психолога — «Слоты» и «Личное». В кабинете Поддержки — «Личное» (смены ставит Админ).

**Меню и Кабинеты:**
- **Клиент:** Найти психолога, Сессии, Сообщения, Планировщик, Профиль.
- **Психолог:** Календарь, Сессии, Сообщения, Личная страница, Отчёты, Профиль.
- **Поддержка:** Чаты (клиентов), Чаты (психологов), Профиль, Календарь.
- **Админ:** Сводка, Заявки, Сообщения, Пользователи, Отчёты, Профиль, Планировщик.

## 5. Ключевые сценарии
- **Видеосвязь (WebRTC):** НЕ ТРОГАТЬ.
- **Бронирование:** `catalog.js` → `psychologist.js` → `confirmBooking()`.
- **Отмена:** `sessions.js` / `psychologist-sessions.js`.
- **Заявка на психолога:** `become-psychologist.js`.
- **Модерация:** `admin.js`.

## 6. Безопасность (RLS)
- RLS включен на всех таблицах.
- Пользователь видит только свои данные (профиль, сообщения, сессии).
- Администратор (Owner) видит всё.
- Поддержка видит чаты клиентов.
- **Анонимность:** психолог не видит реальных ФИО и контактов клиента.
