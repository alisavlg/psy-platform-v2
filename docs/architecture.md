## 2. Технологический стек
- **Фронтенд:** HTML, Vanilla JS (ES Modules), CSS. Сборщик — Vite.
- **Бэкенд:** Supabase (Auth, PostgreSQL, RLS, Storage).
- **Хостинг:** VPS в Serv-Tech (IP `185.170.10.206`).
- **Веб-сервер:** Nginx (раздача статики из `/var/www/eupsy/dist/`).
- **Видеосвязь:** WebRTC + собственный TURN-сервер (Coturn) на VPS.
- **SSL:** Let's Encrypt (Certbot).
- **Почта:** Postfix + OpenDKIM (собственный SMTP на VPS).

## 3. Ключевые принципы архитектуры (Единый код)

**Главный принцип:** Код пишется один раз. Компоненты (Профиль, Календарь, Мессенджер) используются во всех кабинетах, но меняют вид и функционал в зависимости от роли (`window.CURRENT_USER`).

**Роли и кабинеты:**
- У абонента (пользователя) один аккаунт (email, пароль), но может быть несколько ролей.
- При переключении роли меняется кабинет (интерфейс, меню, права), но данные (профиль, календарь, чаты) остаются связанными с одним человеком.

## 5. Ключевые сценарии

### Видеосвязь (WebRTC) — НЕ ТРОГАТЬ
1. Психолог заходит в комнату. Создает `RTCPeerConnection`, отправляет `offer` в таблицу `webrtc_signals`.
2. Клиент заходит в комнату. Polling каждые 2 секунды проверяет `webrtc_signals`.
3. Клиент получает `offer`, создает `answer`, отправляет обратно.
4. Оба обмениваются `ice-candidate`.
5. Соединение устанавливается через TURN-сервер (`turn:185.170.10.206:3478`).
6. **Конфиденциальность:** Клиент всегда анонимен для психолога (псевдоним и аватар).

### Бронирование
`catalog.js` → `psychologist.js` → confirmBooking()
→ DELETE free → INSERT sessions (с `psychologist_user_id`) → INSERT events (психологу и клиенту) → INSERT notifications

### Отмена
`sessions.js` / `psychologist-sessions.js` → status=cancelled
→ возврат free-слота → удаление events → уведомление

### Заявка на психолога
`become-psychologist.js` → загрузка в Storage
→ INSERT applications → триггер пишет в application_events

### Модерация
`admin.js` → RPC (approve / reject / attention)
→ копирование данных в `psychologist_profiles` → отправка уведомления.

## 6. Безопасность (RLS)
- **RLS (Row Level Security)** включен на всех таблицах.
- Пользователь видит только свои данные (профиль, сообщения, сессии).
- Администратор (Owner) видит всё.
- Поддержка видит чаты клиентов (для ответов).
- **Анонимность:** психолог не видит реальных ФИО и контактов клиента.
